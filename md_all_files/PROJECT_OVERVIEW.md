#  Monorepo Accounting App: The Master Guide

यह फ़ाइल आपके प्रोजेक्ट का नक्शा (Map) और गाइड है। यह प्रोजेक्ट का "Single Source of Truth" है, जिसमें सेटअप, आर्किटेक्चर, फीचर्स और भविष्य के प्लान की पूरी जानकारी है।

---

## 1. 🛠️ प्रोजेक्ट सेटअप और गाइड (Project Setup & Guide)

### प्रोजेक्ट संरचना (Project Structure)
यह एक **Monorepo** है, जिसका मतलब है कि सभी ऐप्स एक ही जगह जुड़े हुए हैं:

1.  **`apps/backend`**: Node.js & Express (API सर्वर - प्रोजेक्ट का दिमाग)।
2.  **`apps/web`**: React & Vite (वेब डैशबोर्ड)।
3.  **`apps/mobile`**: React Native & Expo (मोबाइल ऐप)।
4.  **`apps/desktop`**: Electron & React (कंप्यूटर सॉफ्टवेयर)।
5.  **`packages/shared`**: कॉमन कोड (API, Utils, Constants) जो सभी ऐप्स इस्तेमाल करते हैं।

### प्रोजेक्ट को रीस्टार्ट/सेटअप कैसे करें (Clean Install)
अगर आपको कभी भी `node_modules` या वर्जन की दिक्कत आए, तो **Root Terminal** में ये कमांड्स चलाएं:

1.  **सफाई (Clean Old Files)**
    ```powershell
    Remove-Item -Recurse -Force node_modules
    Remove-Item -Force package-lock.json
    ```
2.  **इंस्टॉल (Install Dependencies)**
    ```powershell
    npm install
    ```
3.  **रन (Run Project)**
    - **सब एक साथ:** `npm run dev:all`
    - **सिर्फ वेब:** `npm run web`
    - **सिर्फ बैकएंड:** `npm run backend`
    - **मोबाइल (कैश क्लियर करके):** `npm run mobile -- --clear`

## 2. 🏛️ आर्किटेक्चर और Monorepo रणनीति

### सिद्धांत (Core Principle)
1.  **`apps/*` (UI Layer):** ये सिर्फ "चेहरा" हैं। इनका काम यूजर को इंटरफ़ेस दिखाना और यूजर इनपुट लेना है।
2.  **`packages/shared` (Logic Layer):** यह प्रोजेक्ट का "दिमाग" है। API कॉल्स, डेटा की गणना, और सभी कॉमन फंक्शन यहीं रहते हैं।

### Centralized API Service (`packages/shared/src/services/api.js`)
- **`axios` Instance**: एक ही `axios` इंस्टैंस जो सभी प्लेटफॉर्म्स पर API कॉल्स के लिए इस्तेमाल होता है।
- **Automatic Headers**: हर रिक्वेस्ट में `Authorization` (Token) और `x-company-id` हेडर अपने आप जुड़ जाते हैं।
- **Universal Error Handling**: 401 (Invalid Token) जैसे एरर को सेंट्रली हैंडल करके यूजर को लॉगआउट किया जाता है।
- **Response Unwrapping**: API से मिले `response.data` को पहले ही खोल देता है, ताकि फ्रंटएंड में सीधे `response.companies` जैसा कोड लिखा जा सके।

### Offline-First (Desktop & Mobile)
- **Local Database**: डेटा पहले लोकल (SQLite) में सेव होता है।
- **Sync Queue**: इंटरनेट आने पर `syncqueue.native.js` अपने आप लोकल डेटा को सर्वर पर अपलोड कर देता है।
- **Seamless Experience**: ऐप बिना इंटरनेट के भी पूरी तरह से काम करता है।

## 3. ✨ मुख्य फीचर्स का विवरण (Detailed Features)

### A. इन्वेंटरी मैनेजमेंट (Inventory Management)

#### 1. एडवांस प्रोडक्ट मैनेजमेंट
- **Flexible Schema**: `product.js` मॉडल अलग-अलग बिजनेस (ज्वेलरी, हार्डवेयर, मैन्युफैक्चरिंग) के लिए कस्टम फील्ड्स, रेसिपी (BOM), और कई तरह के प्राइस (MRP, सेल्लिंग, होलसेल) को सपोर्ट करता है।
- **स्टॉक ट्रैकिंग**: रियल-टाइम स्टॉक, परचेस से ऑटोमेटिक स्टॉक बढ़ना, और स्टॉक एडजस्टमेंट।

#### 2. स्मार्ट बल्क इम्पोर्ट (Excel Upload)
- **फ्लेक्सिबल मैपिंग**: "Company", "Group", "Rate 1", "GST %" जैसे अलग-अलग कॉलम नामों को अपने आप पहचान लेता है।
- **स्मार्ट अपडेट**: अगर प्रोडक्ट पहले से मौजूद है (SKU, बारकोड या नाम से), तो यह उसे नया बनाने की बजाय सिर्फ बदली हुई कीमतों को अपडेट करता है।
- **ऑटो-जनरेशन**: अगर SKU या बारकोड नहीं दिया गया है, तो सिस्टम अपने आप बना देता है।
- **चेंज समरी**: इम्पोर्ट के बाद बताता है कि कितने नए प्रोडक्ट बने, कितने अपडेट हुए और किनकी कीमतें बदलीं।

#### 3. स्मार्ट डिलीट
- **Hard Delete**: अगर प्रोडक्ट किसी बिल में इस्तेमाल नहीं हुआ है, तो उसे डेटाबेस से पूरी तरह हटा दिया जाता है।
- **Soft Delete**: अगर प्रोडक्ट बिल में इस्तेमाल हो चुका है, तो उसे सिर्फ `inactive` मार्क किया जाता है ताकि पुराने रिकॉर्ड खराब न हों।

#### 4. कैटेगरी एनालिटिक्स डैशबोर्ड
- **ग्रुप व्यू**: सभी प्रोडक्ट्स को कैटेगरी के हिसाब से ग्रुप करके दिखाता है।
- **समरी कार्ड्स**: हर कैटेगरी में कुल आइटम्स, लो-स्टॉक आइटम्स की संख्या, और कुल स्टॉक वैल्यू दिखाता है।
- **ड्रिल-डाउन**: किसी भी कैटेगरी पर क्लिक करके उसके अंदर के सभी प्रोडक्ट्स की लिस्ट और उनका स्टेटस (Low/OK) देख सकते हैं।

### B. बिलिंग और फाइनेंस (Billing & Financials)

- **बिलिंग और परचेस**: सेल्स बिल और परचेस एंट्री बनाना, जिससे स्टॉक और सप्लायर का बैलेंस अपने आप अपडेट होता है।
- **पार्टी लेजर (उधार खाता)**: कस्टमर और सप्लायर का हिसाब-किताब (कितना लेना है, कितना देना है) मैनेज होता है।
- **UPI QR कोड**: हर बिल के लिए एक डायनामिक QR कोड बनता है, जिसे स्कैन करके ग्राहक सीधे पेमेंट कर सकता है।
- **PDF जनरेशन**: इनवॉइस और रिपोर्ट्स के लिए अलग-अलग टेम्पलेट और कलर थीम के साथ PDF बना सकते हैं।

### C. मोबाइल ऐप फीचर्स (Mobile App)

- **लाइव डैशबोर्ड**: API से कनेक्टेड रियल-टाइम डैशबोर्ड, जो ऑफलाइन भी काम करता है।
- **ऑफलाइन-फर्स्ट**: प्रोडक्ट, पार्टी, बिल, और खर्चों की लिस्ट बिना इंटरनेट के भी देखी और बनाई जा सकती है।
- **PDF और WhatsApp शेयरिंग**: बिल, लेजर स्टेटमेंट, और रिपोर्ट्स का PDF बनाकर सीधे WhatsApp पर शेयर करने की सुविधा।
- **थर्मल प्रिंटिंग**: मोबाइल से सीधे ब्लूटूथ POS प्रिंटर पर बिल प्रिंट करना।
- **रिपोर्ट्स**: GSTR, P&L, और बैलेंस शीट जैसी रिपोर्ट्स मोबाइल पर उपलब्ध हैं।

### D. सुरक्षा और ऑटोमेशन (Security & Automation)

- **ऑडिट लॉग**: सिस्टम में कौन क्या कर रहा है (जैसे बिल बनाना, प्रोडक्ट डिलीट करना), हर चीज़ का रिकॉर्ड `SecurityLog` में रखा जाता है।
- **रेट लिमिटिंग**: DDoS अटैक और ब्रूट-फोर्स से बचाव।
- **डेटा वैलिडेशन**: `Zod` का उपयोग करके गलत डेटा को API लेवल पर ही रोक दिया जाता है।
- **Cron Jobs**: `node-cron` का उपयोग करके ऑटोमेटेड टास्क (जैसे पेमेंट रिमाइंडर) चलाए जा सकते हैं।
