## चरण 2: प्रत्येक फ़ाइल का विश्लेषण कैसे करें

ऊपर दी गई सूची में प्रत्येक फ़ाइल के लिए, अपने आप से ये प्रश्न पूछें:

1.  **क्या यह एक पुराना, अप्रयुक्त कंपोनेंट है?**
    *   **उदाहरण:** हो सकता है `ScheemApplyModel.jsx` अब इस्तेमाल में न हो क्योंकि आपने स्कीम लॉजिक को बदल दिया है।
    *   **निर्णय:** यदि हाँ, तो यह वास्तव में एक अनाथ फ़ाइल है।

2.  **क्या यह एक हटाए गए फ़ीचर का हिस्सा है?**
    *   **उदाहरण:** आपके `git status` से पता चलता है कि `expenses` (खर्च) से संबंधित कई फ़ाइलें हटा दी गई हैं। हो सकता है कि `AddExpansePage.jsx` उसी का एक बचा हुआ हिस्सा हो।
    *   **निर्णय:** यदि हाँ, तो यह वास्तव में एक अनाथ फ़ाइल है।

3.  **क्या यह फ़ाइल डायनामिक रूप से इम्पोर्ट होती है?**
    *   **उदाहरण:** कुछ फ़ाइलें (जैसे `React.lazy` से लोड होने वाले पेज या कुछ इमेज) सीधे इम्पोर्ट नहीं होती हैं। ऑडिट स्क्रिप्ट उन्हें गलती से अनाथ समझ सकती है।
    *   **निर्णय:** यदि हाँ, तो यह एक "false positive" है और इसे डिलीट नहीं करना है।

## चरण 3: एक्शन - फ़ाइलों को कैसे ठीक करें

### अगर फ़ाइल सच में अनाथ है:

इसे अपने प्रोजेक्ट से सुरक्षित रूप से हटा दें। यह आपके कोडबेस को साफ़ रखेगा।

**कमांड:**
```bash
git rm [file_path]
```
**उदाहरण:**
```bash
git rm apps/desktop/src/screens/expanses/AddExpansePage.jsx
```

### अगर फ़ाइल "False Positive" है:

कुछ न करें। फ़ाइल को प्रोजेक्ट में रहने दें। आप भविष्य में अपनी ऑडिट स्क्रिप्ट को बेहतर बना सकते हैं ताकि वह ऐसे मामलों को पहचान सके।
